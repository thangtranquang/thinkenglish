# ReflexEnglish – project conventions

Visual-first English reflex app for Vietnamese school students (11–18, CEFR A1–B1). Look at a photo, say the English word fast. UI language is Vietnamese; learning content is English.

Source of truth: `docs/Product_Specification_ReflexEnglish_v1.1.docx` (readable extract: `docs/spec_v1.1.md`). Clickable prototype to port: `docs/reflex_app.html` (vanilla JS SPA with mock data). Pre-generated TTS: `docs/audio/*.mp3` (generated by `tools/gen_audio.py`, file name = slug + djb2 hash of the text).

## Stack (decided)
- **Backend:** Python 3.11+, FastAPI, SQLite (stdlib `sqlite3`, WAL mode, foreign keys ON), pydantic v2 for every request/response model.
- **Passwords:** stdlib `hashlib.scrypt` with per-user salt. No other crypto deps.
- **Frontend:** vanilla JS (ES modules) + plain CSS, served as static files by FastAPI. No build step, no framework.
- **AI:** one provider interface (`AIProvider.analyze(image_bytes) -> AnalysisResult`). `GeminiProvider` is used only when `GEMINI_API_KEY` is set; `MockProvider` is deterministic and is what all tests use.
- **Tests:** pytest + httpx `TestClient` for backend; Playwright (Python) for e2e. Run: `python -m pytest`.
- **Run:** `python -m uvicorn backend.app.main:app --reload` (from repo root).

## Layout
```
backend/app/
  main.py            app factory, static mount, router wiring
  config.py          settings from env (no secrets in code)
  db.py              connection factory, schema migration runner
  security.py        scrypt, token hashing, csrf helpers
  deps.py            FastAPI dependencies (current identity, csrf check)
  routers/           HTTP only: parse/validate, call services, shape responses
  services/          business rules (guest, auth, cards, practice, srs, upload)
  repositories/      all SQL lives here, parameterized only
  ai/                provider.py (interface), mock.py, gemini.py
  seed.py            idempotent seed of system cards + audio_assets
backend/migrations/  numbered .sql files (001_init.sql ...)
backend/tests/       pytest
frontend/            index.html, css/, js/ (api.js, state.js, screens/*.js), audio/ (mp3)
e2e/                 Playwright tests
tools/               gen_audio.py and other dev scripts
docs/                spec, PRD.md, use-cases/, qa/
```
Dependency direction: `routers → services → repositories → db`. Routers never run SQL; repositories never import FastAPI; `ai/` is only called from `services/upload`.

## Hard rules
- SQL: parameterized queries only; never build SQL with string formatting.
- Every endpoint validates input with a pydantic model; reject unknown fields.
- Auth cookies: `HttpOnly`, `SameSite=Lax`, `Secure` when not on localhost. Session/guest tokens are random 256-bit, stored **hashed** (sha256) server-side.
- State-changing requests (POST/PUT/PATCH/DELETE) require CSRF protection (double-submit token header + Origin check).
- Never log or return password hashes, tokens, or guardian emails.
- Uploads: allow only JPEG/PNG/WebP, size cap, re-encode with Pillow to strip EXIF/GPS; store only the cleaned image.
- Photos are private by default; public visibility requires `moderation_status = 'approved'`.
- AI is called at most once per unique image (sha256). A second upload of the same bytes reuses `card_contents`.
- No secrets in git: `.env` is ignored, ship `.env.example`.
- Personal data stays minimal: nickname (no real name), avatar key, birth year, guardian email (only if under 16).

## Conventions
- Git: branch `feat/<slug>`, conventional commits with scope in `api | ui | db | auth | core | infra`, one slice = one commit, never push, no AI attribution lines in commit messages.
- Python style: type hints everywhere, small functions, no global mutable state besides the DB connection factory.
- Frontend: never use `innerHTML` with dynamic data (use `textContent` / DOM builders). Keep markers ≥44px touch targets.
